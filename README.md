# Math Trace Validity

Checks whether Chain-of-Thought (CoT) traces generated by [Goedel-Prover](https://huggingface.co/Goedel-LM/Goedel-Prover-SFT) are valid Lean4 proofs. Uses the [FormalStep](https://huggingface.co/datasets/liuchengwu/FormalStep) dataset and verifies generated Lean4 code using a local Lean4 REPL via [lean_interact](https://github.com/lean-dojo/lean-interact).

## Project Structure

```
math-trace-validity/
├── trace_valid.py      # Main CLI entry point
├── config.py           # Constants: model name, dataset, Lean config, paths
├── data_loader.py      # FormalStepDataset class (wraps HuggingFace dataset)
├── model.py            # GoedelProver class (load model, generate trajectories)
├── parser.py           # BPE repair + Lean4 code extraction from raw output
├── verifier.py         # LeanVerifier class (Lean project setup + verification)
├── analysis.py         # Stats computation, bar charts, temperature sweep plot
├── requirements.txt    # Python dependencies
├── setup_lean.sh       # One-time Lean4 / elan / Mathlib setup
├── colab_run.sh        # Quick-start script for Google Colab
└── results/            # Output directory for JSON results and plots
```

## Setup

### 1. Clone the repo

```bash
git clone https://github.com/YOUR_USER/math-trace-validity.git
cd math-trace-validity
```

### 2. Install Python dependencies

```bash
pip install -r requirements.txt
```

### 3. Install Lean4 and fetch Mathlib

```bash
bash setup_lean.sh
```

Installs `elan` (Lean version manager), the pinned Lean toolchain, and fetches
Mathlib **from the prebuilt cache**. Mathlib is never compiled from source.

#### Version pinning — do not bump these independently

| Component | Pin | Where |
|---|---|---|
| Lean toolchain | `leanprover/lean4:v4.32.0` | `config.LEAN_VERSION`, `lean_project/lean-toolchain` |
| Mathlib | tag `v4.32.0` | `lean_project/lakefile.toml` |
| REPL | `augustepoiroux/repl` @ `v1.3.18` | resolved by `lean_interact` |

`lean_interact` selects its REPL by checking out a tag named
`{repl_rev}_lean-toolchain-{lean_version}`. That rev publishes 94 such tags,
topping out at `v4.32.0` — **there is no `v4.32.2` tag**. A project on Mathlib
`v4.32.2` (whose `lean-toolchain` is `v4.32.2`) therefore runs against a
mismatched REPL and produces `unexpected token` / `unknown constant`. Because
mathlib4 tag `vX.Y.Z` always declares `leanprover/lean4:vX.Y.Z`, naming the
Mathlib tag after the Lean version is what keeps all three aligned.

Also set a default toolchain, or `lake` fails outside the project directory
(`no default toolchain configured`):

```bash
elan default leanprover/lean4:v4.32.0
```

The project's own `lean-toolchain` still overrides this inside `lean_project/`.

#### Windows: add Defender exclusions first

Mathlib is ~8,600 `.olean` files. With Defender real-time protection scanning
each read, loading it measured **7 KB/s at 0% CPU** and never completed. With
exclusions it loads in ~182s. In an **Administrator** PowerShell:

```powershell
Add-MpPreference -ExclusionPath "<repo>\lean_project"
Add-MpPreference -ExclusionPath "$env:USERPROFILE\.elan"
Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\Programs\Python\Python313\Lib\site-packages\lean_interact"
```

This is the single highest-impact setup step on Windows. Linux needs none of it.

### 4. Verify the install

```bash
python tests/test_verifier.py
```

Runs 35 hand-labelled Lean snippets and prints a confusion matrix. If Lean is
healthy this completes in seconds of verification time (after a one-time
Mathlib load) and agreement should be at or near 100%.

## Usage

### Single temperature run

```bash
python3 trace_valid.py --temp 0
```

This will:
1. Load 50 samples from FormalStep
2. Generate 10 trajectories per sample using Goedel-Prover (temperature=0)
3. Parse and verify each trajectory in Lean4
4. Save results to `results/results_temp_0.0.json`
5. Generate a bar chart at `results/analysis_temp_0.0.png`

### Temperature sweep

```bash
python3 trace_valid.py --temp 0 0.2 0.5 0.8 1.0
```

Runs experiments at all 5 temperatures and produces:
- 5 JSON result files (`results/results_temp_{T}.json`)
- 5 individual bar charts
- 1 sweep line plot (`results/temperature_sweep.png`) showing trace validity and accuracy vs temperature

### Custom sample/trajectory count

```bash
python3 trace_valid.py --temp 0 --num-samples 10 --num-trajectories 5
```

### Re-run analysis only (no GPU inference)

```bash
python3 trace_valid.py --analyze-only --temp 0 0.2 0.5 0.8 1.0
```

## Module Usage

Each module can be imported independently for experimentation:

```python
from data_loader import FormalStepDataset
from model import GoedelProver
from parser import parse_output
from verifier import LeanVerifier

dataset = FormalStepDataset(num_samples=5)
prover = GoedelProver()
verifier = LeanVerifier()

problem, ground_truth = dataset[0]
outputs = prover.generate(problem, temperature=0.0, num_trajectories=1)
parsed = parse_output(outputs[0], prompt=problem)
result = verifier.verify(parsed["code"])
print(result)  # {"valid": True/False, "errors": [...], "num_errors": N}
```
