## The arithmetic split is NOT ANSWERABLE with the current labeller

The question was whether `proof_false` — a failure caused by a number the MODEL wrote — stays at zero on whole-problem olympiad Number Theory, as it did on FormalStep.


**It cannot be answered from this run.** Two reasons, in order of severity:


1. **The labeller evaluated 0 proof-side claims across all 62 failures.** A zero from a denominator of 0 is guaranteed by construction, not measured. `ARITHMETIC_FINDINGS.md` § Limits documents the same problem on FormalStep: 1 claim assertable across 55 failures.

2. **Before the `%` fix it reported 9 `proof_false`, and all 9 were spurious** — `a^2 % 3 = 1` misread as `3 = 1`. Nine flags, nine false positives, so it had no demonstrated precision on modular arithmetic. The fix stops the misreads but does not make modular claims checkable.


Labels actually assigned, reported for completeness and not as a result:


| label | n | share |
|---|---|---|
| `tactic_mismatch` | 40 | 65% |
| `UNKNOWN` | 16 | 26% |
| `budget` | 2 | 3% |
| `parse_skew` | 2 | 3% |
| `noop_tactic` | 2 | 3% |

`UNKNOWN` at 26% is itself a signal that the labeller — built and validated against FormalStep's shapes — does not transfer cleanly to olympiad statements.


## Do not compare this to the 72%

The FormalStep figure is **step-level**: one row per chain-of-thought step, ~62 per problem. This is **problem-level**: one row per whole problem. Different units.


The step-level number is additionally inflated by a triviality mode this dataset structurally cannot produce — see `STEP_VS_PROBLEM_TRIVIALITY.md`. All 90 statements here classify `6_contentful` under the same six probes, so **these pass rates need no content-rate correction**; 31% is already a content rate.
